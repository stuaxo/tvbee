# tveee debloat profile. One entry per line; after the fields, the rest of the
# line is the reason, shown by `tveee debloat list` and `status`.
#
#   profile   <name>
#   model     <ro.product.model this was made for>   (warns on other TVs)
#   disable   <tag> <package>  <reason>      pm disable-user --user 0 (restore: pm enable)
#   uninstall <tag> <package>  <reason>      pm uninstall --user 0 (restore: install-existing)
#   keep      <tag> <package>  <reason>      never changed; re-enabled by `apply` if found off
#   setting   <tag> <namespace> <key> <value>  <reason>   (original recorded, restorable)
#   note      <text>                         shown with the plan
#
# Tags group the entries (`--only` / `--skip` pick groups):
#   telemetry, voice, discontinued, sync, phoneservices, games,
#   speed          only applied on low-spec TVs (unless --only speed)
#   system         keep: a core part of the system
#   dependency:<package>[,<package>...]   keep: these packages need it
#
# Everything here is reversible: system apps are disabled or removed for
# user 0 only, never deleted. No root needed.

# No phone apps exist on this TV, but these are core parts of it:
keep      system        com.android.providers.contacts            the account framework and Telecom expect it at boot
keep      system        com.android.providers.blockednumber       the account framework and Telecom expect it at boot
keep      system        com.android.bluetooth                     the whole Bluetooth stack, not a phone thing
# Decided not to disable (some guides for newer TVs do): despite the name it's
# part of Philips' TV framework, runs as the system user (uid 1000) with
# platform permissions, and is started at boot. Not worth the risk for ~15 MB.
keep      system        org.droidtv.tv.frameworklogger            Philips TV framework part: runs as the system user; left on deliberately

# Tried and put back (2026-09-16): disabling the first two broke the
# Philips/Zeasn NetTV portal. Arte, iPlayer, Dailymotion etc.
# (org.droidtv.nettvapp<NNNN>) launch via org.droidtv.nettv_launcherapp, which
# needs nettvregistration's cloud session check; without it they bounce back to
# live TV, and the "Philips apps" gallery (org.droidtv.nettv.market) shows a
# blank screen.
keep dependency:org.droidtv.nettv_launcherapp,org.droidtv.nettv.market org.droidtv.nettvregistration  its session check lets the NetTV apps (iPlayer, Arte, Dailymotion) and the app gallery open
keep dependency:org.droidtv.nettv_launcherapp org.droidtv.nettvrecommender  disabling it with nettvregistration broke the NetTV apps; keep both
keep dependency:com.android.bluetooth com.android.server.telecom  tangled into Bluetooth audio routing

note com.mxtech.videoplayer.ad (ad-supported MX Player) was fully removed by hand; it can't be restored without the APK. MX Player Pro is still installed.
note Not settable over adb, do these in the TV's menus: Developer options > Background process limit; Play Store > Settings > Auto-update apps; Philips "share usage data" and Google "Usage & diagnostics".
